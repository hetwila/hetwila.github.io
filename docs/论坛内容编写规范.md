# 论坛内容编写规范

适用于当前静态论坛。一个主题是一份 Markdown 文件，全部楼层按原顺序放在同一文件中，不需要拆成几百份文件，也不需要填写百科来源、人物 UID 或关系表。

论坛是独立的世界内作品。讨论中的意见、猜测、推荐书名和同人情节保留在本帖，不自动建立百科、故事条目或反向链接；正文中的人物名也不会自动变成百科链接。

## 1. 交付原稿

可以直接交付以下格式，不需要了解网站代码。首行是帖子完整标题，第二段是社区、版块和分类，随后用分隔线开始楼层。每个楼层标记必须单独成段。

```markdown
# 帖子完整标题

社区名称 › 版块名称 › 讨论分类

---

**1L｜楼主 昵称甲**

第一楼的正文。

**2L｜昵称乙**

回复正文，可以分成多个段落。

**3L｜昵称甲**

楼主的后续发言。
```

- 文件使用 UTF-8，名称保留中文。
- `L` 为大写字母；分隔昵称使用全角竖线 `｜`。
- 从 1L 起连续编号，不重号、不漏号。楼主第一次发言标注 `楼主 `（后有一个空格）。后续发言通过完全一致的昵称识别，不需要重复标注。
- 发言可以包含普通 Markdown 段落、强调、列表和引用。代码块或引用块中的楼层示例不另算一楼。不要用 HTML、Vue 或 MDC 组件制作版式。
- 每层至少有一段内容。楼层标记不可兼作其他用途；讨论中提到楼层，写普通 `4L` 即可。
- 不补造原稿未给出的时间、点赞、浏览量、签名、头像照片或用户资料。当前模板只有昵称首字头像，统计由实际楼层计算。
- 附件文件名中的日期是素材名称的一部分，不自动解释为世界内发帖时间。

## 2. 仓库中的编辑文件

维护者保留原稿原字节到 `sources/forum/<原文件名>.md`，将其 SHA-256 登记到同目录的 `manifest.json`。不要为了改变页面排版而修改原稿。

阅读版位于 `content/forum/<routeKey>.md`。在 YAML frontmatter 中填写主题资料，正文从 1L 开始；不再复制原稿的一级标题、面包屑和分隔线。下面是可复制的格式示意，需替换示例文字；默认是草稿，不会公开：

```markdown
---
uid: thread:中文主题名
routeKey: 中文主题名
title: 帖子完整标题
description: 一两句话介绍这场讨论，便于在主题列表中选择。
community: 社区名称
board: 版块名称
category: 讨论分类
narrativeLayer: in-world-discussion
scopeUid: thread:中文主题名
publicationStatus: draft
visibility: public
settingVersion: 3.0.3
revision: 1
originalFile: 原稿文件名.md
---

**1L｜楼主 昵称甲**

与原稿一致的第一楼正文。

**2L｜昵称乙**

与原稿一致的第二楼正文。
```

全部页首字段如下，均为必填，不接受额外字段：

| 字段 | 填写规则 |
| --- | --- |
| `uid` | `thread:` 开头的稳定身份；后半允许中文等字母、数字、中点 `·`、半角括号和连字符。不随标题改名变动 |
| `routeKey` | 简短、明确的中文主题名；文件名必须是 `<routeKey>.md`。遵循百科同样的中文路径字符规则；不能有 `/`、`#`、`?`、`%`，不能用 `index`、`category`，最长100字符，NFC规范化 |
| `title` | 原稿完整标题，包括作者的题头标签和标点；可以比 routeKey 更长 |
| `description` | 用于列表和搜索的简介；不替换楼主正文 |
| `community` / `board` / `category` | 原稿面包屑中的社区、版块、分类，三者顺序与名称完全对应 |
| `narrativeLayer` | 固定为 `in-world-discussion` |
| `scopeUid` | 必须与本帖 `uid` 相同 |
| `publicationStatus` | `draft`、`review`、`published`、`withdrawn` |
| `visibility` | `public` 或 `private`；只有 `published + public` 会生成网页与导出 |
| `settingVersion` | 当前固定为字符串 `3.0.3` |
| `revision` | 正整数，从1开始；公开内容修订时递增 |
| `originalFile` | `sources/forum/` 下的原稿文件名，只填文件名，不含目录 |

不要填写百科的 `sourceRefs`、`factStatus`、`relations`、`events`，也不要手工填写回复数、参与人数、分页、楼层 UID、路径或下载地址。论坛有独立 schema，不能套用百科模板。

原稿必须与阅读版的标题、版块资料、每层昵称、楼主身份和正文一致。导入时可增补元数据，不能悄悄改写发言。构建逐层比较原稿和阅读版（忽略楼层正文两端的空白）；若作者提供修订原稿，应整体核对后更新原稿、阅读版和校验值，不能通过只改哈希绕开不一致。

## 3. 页面与楼层链接

- `/forum` 按社区、版块汇总已公开主题。
- `/forum/threads/<routeKey>/page/<页码>` 每页20层，1为第一页。
- `/forum/threads/<routeKey>/author/page/<页码>` 是“只看楼主”；每页20条楼主发言，保留原楼层号，不重新编号。
- 楼层链接指向完整讨论中的对应页和 `#post-<楼层号>`，例如第61楼是 `/forum/threads/皇族历史同人讨论/page/4#post-61`。只看楼主中的永久链接也回到完整上下文。
- 文本中的 `4L` 等普通楼层引用自动链接到本帖已存在的楼层，现有 Markdown 链接和代码中的文字不改写。
- 已发表的楼层号是身份的一部分，追加内容放在末尾，不能通过插入、删除或重排让原楼号指向另一个发言；当前未实现逐层撤回，需撤回时使用主题级 `withdrawn`。

每层 UID 从稳定主题身份和楼层号生成，例如 `post:皇族历史同人讨论:61`。页大小与楼层顺序属于公开链接约定；当前不另外生成楼层永久页或旧地址跳转页。

## 4. 导入与检查

在已有开发环境的仓库根目录执行 `pnpm prepare:content`；云环境用 `bash scripts/cloud.sh prepare:content`。不要与 Nuxt dev 的内容监听器同时运行。修改界面后还需执行类型检查、内容测试、静态生成和浏览器测试，命令见 [README](../README.md)。

构建检查并拒绝：重复主题身份／路径、文件名不一致、错误 scope、额外字段、原稿校验失败、原稿与阅读版不一致、空楼层、楼号缺失／重复、冒认楼主。

未发表或私密主题不会进入 Nuxt Content、静态路由、搜索、HTML、Markdown 或 JSON。公开 Git 仓库本身仍然公开，真正私密的素材不能提交进去。

楼层渲染复用 Nuxt Content 的 `ContentRenderer`；`.generated/content/forum/` 是构建生成的每层 Markdown，不能直接编辑。所有普通页和只看楼主页都预生成 HTML，关闭 JavaScript 仍可翻页、阅读和沿楼层引用跳转。

## 5. AI 直接读取

先获取 `/data/v1/manifest.json`，沿 `forum` 字段读取独立的主题目录 `forum.json`。目录内每个主题提供：

- `markdownUrl`：完整主题编辑版；`originalMarkdownUrl`：原字节原稿；`originalSha256`：校验值。
- `jsonUrl`：主题元数据、全部 `posts` 和静态 `pages` 路径，一次请求即可读取全部楼层。
- 每层包含 `uid`、`threadUid`、`scopeUid`、`narrativeLayer`、`floor`、`author`、`isOriginalPoster`、`bodyMarkdown`、`path`。时间与互动数据未提供时不输出猜测值。

`forumThreadCount`、`forumPostCount` 是清单中的独立统计；`documentCount` 继续仅统计百科与故事。论坛不加入 `catalog.json`、`relations.json`、`events.json` 或来源映射，搜索结果明确标识“世界内论坛”。只看楼主的重复阅读视图不再索引。

全文、楼层和元数据可直接通过 HTTP 获取，无需浏览器截图、OCR 或登录。未来真实用户投稿与互动由后端 API 承接，目前没有发布或回帖 API，也不显示无法使用的发表按钮。
