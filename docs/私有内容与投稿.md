# 私有内容与投稿

私有百科、故事和世界内论坛保存在 Supabase。公开的 Git Markdown、原稿哈希和静态导出仍使用原有流程。私有内容默认仅管理员可见，发布后可以逐篇授予用户或用户组阅读权限；不会把私有稿件自动发布到公开百科、故事书架或论坛。

## 使用入口

| 路径 | 用途 |
| --- | --- |
| `/private` | 列出当前用户可阅读的私有内容，支持按百科、故事、论坛筛选 |
| `/account/submissions` | 投稿列表；管理员看到全部内容 |
| `/account/submissions/edit` | 创建稿件；`?id=<UUID>` 编辑已有稿件和设置阅读权限 |
| `/private/<UUID>` | 部署时生成的独立阅读地址 |
| `/private/read?id=<UUID>` | 预先生成的通用阅读页；新投稿在下一次部署前也可阅读和刷新 |

用户中心提供“可阅读内容”和“内容与投稿”入口；管理中心另有“内容与投稿”标签。公开百科、故事和论坛的列表页提供对应的授权内容入口，但不在公开 HTML 中展示私有标题。

投稿表单包含类型、年龄分级、标题、简介、分类、作品署名和 Markdown 正文。论坛按楼层填写作品昵称与正文，楼号连续，每页20层；首层昵称决定楼主标记。昵称属于作品，不关联真实网站账号。楼内同人文使用与公开论坛相同的成对 `fanfiction` 边界、二级篇名和三级章节，聊天与同人文可以混排。预览与阅读复用现有 `article-prose`、`forum-post` 和 `ForumFanfiction` 排版。

新稿默认草稿。管理员可切换为已发布，再在“阅读权限”中勾选用户组或查找并选择用户。支持按昵称、邮箱或完整 UUID 查找；昵称可重复，应核对邮箱和 ID。没有任何授权时仍仅管理员可读。保存正文与保存阅读权限是两个明确的操作；调整权限不会覆盖尚未保存的正文。

## 年龄分级与阅读偏好

私有百科、故事和论坛统一支持“一般”与“R-18”，数据库字段为 `age_rating: general | r18`。新稿及迁移前已有稿件默认为一般，投稿表单可选择或修改分级；论坛分级适用于整帖所有楼层及其中的同人文。分级变更也更新 `updated_at`，参与现有的并发修改检查。

两种内容始终出现在当前用户有权阅读的目录中，均带可读的分级标记；R-18 使用 warning badge。关闭敏感内容默认显示时，目录仍显示标题、分级与署名，但不展示 R-18 简介；阅读页先请求不含正文或楼层的摘要，确认分级后才请求全文。全文响应会再次检查分级，避免两次请求之间的修改导致直接展示。

个人中心的“阅读偏好”（`/account#reading-preferences`）提供“默认显示敏感内容（R-18）”。`account_profiles.show_sensitive_content` 默认为 `false`，仅本人可以修改；管理员也不能替其他用户修改。开启表示已年满18周岁，需点击“保存阅读偏好”才会持久保存。未开启、旧资料缺少该字段或资料读取失败时，R-18 阅读页显示年龄确认、返回目录按钮和资料设置链接。

单次确认只保存在当前阅读组件内，不修改资料、不写 cookie 或浏览器存储。当前帖内翻页、只看楼主和章节跳转继续有效；刷新、离开后重进、切换文章、切换账号或注销后重新确认。年龄分级是展示偏好，不是额外的身份认证或阅读授权；无论设置或确认结果如何，数据库仍按已有用户／用户组权限校验每次读取。投稿编辑与预览属于显式的管理操作，可直接维护 R-18 原稿。

## 权限规则

| 操作 | 未登录 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 读取正文、标题及简介 | 不允许 | 已发布且获得本人或用户组授权 | 全部草稿与已发布内容 |
| 投稿 | 不允许 | 当前关闭；由数据库中的用户组能力决定 | 当前允许 |
| 编辑、删除稿件 | 不允许 | 将来开放投稿后，仅本人仍可投稿的草稿 | 全部 |
| 发布、撤回为草稿 | 不允许 | 不允许 | 允许 |
| 查看及修改阅读授权 | 不允许 | 不允许 | 允许 |
| 读取静态路由清单 | 仅不透明 URL | 仅不透明 URL | 仅不透明 URL |

用户授权与用户组授权为“或”关系。移除某一种授权后，另一种有效授权仍允许阅读；撤回为草稿会停止向所有普通获授权读者开放。管理员通过 `account_profiles.user_group` 判断，不能通过可写的 `user_metadata` 提权。每次数据库请求均检查当前资料和授权，既有 JWT 不会保留已撤销的用户组权限。

`content_submission_permissions` 初始为 `admin=true`、`guest=false`。浏览器没有修改此表的权限；以后开放投稿只需通过受控迁移为相应 `account_group` 配置能力。新增组同时扩展既有账号组枚举及其成员管理；阅读授权选择器从数据库枚举读取，无需硬编码新的选项。开放投稿不会自动授予发布、授权管理或编辑别人稿件的能力。

## 数据与 API

| 表／函数 | 用途 |
| --- | --- |
| `private_documents` | UUID、类型、标题／简介／分类／署名、Markdown 或有序论坛楼层、草稿／发布状态、年龄分级、投稿者、时间及授权版本 |
| `content_user_grants` | 文章 UUID → 用户 UUID 的阅读授权 |
| `content_group_grants` | 文章 UUID → 账号组的阅读授权 |
| `content_submission_permissions` | 按账号组控制投稿能力 |
| `private_content_routes` | 唯一 `path` 字段，只含 `/private/<UUID>` |
| `content_can_submit()` | 当前调用者是否可以投稿 |
| `content_account_groups()` | 现有账号组枚举，供授权表单使用 |
| `content_set_access(...)` | 管理员原子替换一篇稿件的用户、用户组授权 |

接口契约见 [`private-content.openapi.json`](../public/api/private-content.openapi.json)。普通 HTTP 客户端使用公开 `apikey` 和用户会话的 Bearer token。读取列表显式选择摘要字段，按 `created_at.desc,id.asc` 排序，并使用 `limit,offset` 和 `Prefer: count=exact` 分页。读取单篇用 `/rest/v1/private_documents?id=eq.<UUID>`。RLS 将无权读取和不存在的对象都隐藏，前端统一显示“内容不可用”。

浏览器只能写入允许的正文列，不能指定 UUID、投稿者、时间或授权版本；类型在创建后不可修改。数据库同时验证标题、正文、楼层结构、大小与发布权限。文章最多500000字符；论坛最多1000层，每层200000字符，整个楼层 JSON 最多2000000字节，表单提前预留少量编码余量。

正文修改与删除附加旧 `updated_at=eq.<时间>` 条件，并检查返回行数。空结果代表目标已变化或当前没有权限，表单保留尚未保存的正文。授权修改使用 `p_expected_version`，在同一事务内锁定目标、替换两组授权并递增 `access_version`。版本冲突返回 SQLSTATE `40001`；无效用户会回滚整个事务。授权变化不推进正文的 `updated_at`，避免权限表单掩盖另一窗口的正文冲突。删除正文会级联删除授权，但保留不透明 URL，使旧书签仍能打开中性提示页。

## 内容与会话隔离

私有 Markdown 是数据，不解释 HTML、MDC 或 Vue 组件；渲染使用固定 Vue 标签白名单。支持标题与目录、强调、列表、引用、表格、代码和安全 HTTP(S) 链接／图片，锚点按文章和楼层隔离。同人文只把经过解析的边界交给既有组件，不执行作者提供的组件属性。公开评论继续使用原有的标题降级与10000字符上限。

正文仅在浏览器登录后经 RLS 获取，不使用服务角色，不进入 Nuxt SSR payload、Nuxt Content、Pagefind、公开世界观数据或 localStorage。网络请求使用 `no-store`；切换账号、退出登录、离开阅读页、隐藏标签页时清除当前正文并取消未完成的请求，重新显示标签页或从浏览器页面缓存返回时重新校验。已合法读取并由读者自行保存的内容无法远程收回；撤权约束后续请求，不是实时推送删除。阅读请求有20秒超时和可重试状态。

禁用 JavaScript 时只显示登录与启用脚本提示；公开文章继续支持无脚本阅读。所有私有入口带 `noindex`，不进入公开搜索。这里尚未接入读者评论，避免复用公开评论区时泄露私有标题或讨论。

## GitHub Pages 构建

主分支工作流在 `pnpm generate` 时设置 `PRIVATE_CONTENT_ROUTES=required`，通过公开 key 分页读取 `private_content_routes?select=path`。构建不读取 `private_documents`，不持有管理员会话，也不需要增加 GitHub Secrets。清单请求失败、格式异常、重复／乱序路径或超出限制时停止发布，避免悄悄漏掉页面。

每个 UUID 对应一个空壳 HTML；论坛用 `?page=2` 和 `?author=1` 切换范围，不因新增楼层需要更多静态文件。`#post-21` 永久链接始终回完整讨论。所有页面都在访问时再请求正文；标题、正文、作者、授权名单和草稿状态不会随路由清单发布。`/private-routes.json` 仅记录本次构建的 URL，用于部署后的逐页 HTTP 校验。URL 的存在会公开，阅读权限始终由数据库保护。

构建后由 `scripts/verify-private-output.ts` 核对每个空壳，部署后的工作流检查独立地址及通用入口。新稿尚无独立 HTML 时，网页自动使用 `/private/read?id=...`，可以直接访问和刷新；下一次部署会自动切换为独立地址。下次构建不会把私有正文静态化。普通离线开发／类型检查不设置 `PRIVATE_CONTENT_ROUTES`，仍可使用通用阅读页。

## 部署与验证

先完成类型检查、账号／RLS 集成测试和前端测试，再使用仓库既有 Management API 历史部署新增迁移：

```bash
bash scripts/cloud.sh typecheck
bash scripts/cloud.sh test:accounts
bash scripts/cloud.sh test
NODE_USE_ENV_PROXY=1 bash scripts/cloud.sh content:deploy
NODE_USE_ENV_PROXY=1 bash scripts/cloud.sh content:verify
```

`content:deploy` 复核历史迁移哈希、仅应用新迁移并读取安全 advisors；不会重置 Auth 配置、管理员密码、注册函数或评论关联。随后推送 `main`，Pages 主分支构建会自动读取路由清单；数据库迁移必须先于该构建。重复部署不会重置既有稿件和授权。

`content:verify` 也验证分级默认值／取值约束、分级修改与阅读偏好的默认关闭和本人修改边界。在已部署数据库的同一事务内创建临时资料与稿件，切换数据库角色／JWT claims 检查 RLS 后完整回滚，再复核无残留，并用真正的匿名 HTTP 请求验证私有表拒绝访问、仅路径清单可读。它不创建持久测试账号、不发邮件、不登录或修改真实管理员账号；这项检查不等同于真实浏览器登录验收。

`test:accounts` 使用临时 PostgreSQL、Auth 和 PostgREST 验证真实权限；`test:private-build` 通过本地只提供路径的 HTTP 服务执行真实静态生成、检查空壳与私密变量隔离，不访问生产 Supabase。`pnpm test` 在这个静态产物上运行浏览器测试。GitHub 工作流先运行该构建测试，再以正式的公开配置重新生成可部署产物。浏览器测试使用拦截响应，覆盖阅读、退出／撤权、投稿与权限表单、同人文和分页、错误恢复、桌面／手机及明暗主题；本地模拟与真实云端验收应分别记录。
