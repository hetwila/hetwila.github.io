## 页面与权限

| 地址 | 功能 |
| --- | --- |
| `/account` | 查看用户组；修改自己的昵称、头像与密码；退出登录 |
| `/account/login` | 邮箱与密码登录 |
| `/account/register` | 邮箱、密码两次、邀请码、昵称、可选头像、Turnstile |
| `/account/admin` | 管理邀请码、分页查看所有注册用户，仅 admin 可用 |

站点导航会携带 `returnTo`。注册成功后自动登录并返回原阅读地址；校验器只接受站内地址，拒绝外站与登录／注册循环。账号创建后自动登录或头像上传失败，不会再次注册或再次核销邀请码。

当前只有 `guest` 和 `admin`。新注册者为 guest；昵称可以重复，用户 ID 是唯一身份。guest 只能读取并修改自己的资料；admin 可以读取全部用户、创建／修改／删除邀请码。当前没有管理员编辑其他人资料、封号、修改用户组的页面，也没有忘记密码、邮件找回或实际论坛回帖功能。

注册不验证邮箱归属，后端在创建账号时直接标记邮箱确认，不发送邮件。管理员初始化不会仅凭邮箱提升一个已有账号的权限，避免将冒用邮箱的账号变成管理员。

## 环境变量

参考仓库根目录 `.env.example`。本地可使用忽略提交的 `.env`；Codex 云环境配置的变量必须实际挂载到正在运行的任务，保存环境设置不一定会刷新已有实例。用 `pnpm accounts:check` 检查是否已加载；该命令只输出变量名与状态。

| 变量 | 使用位置 |
| --- | --- |
| `SUPABASE_PROJECT_ID` | 运维脚本指定项目 |
| `SUPABASE_URL` | 公开项目 URL；静态构建与运维 |
| `SUPABASE_KEY` | 公开 publishable key，兼容旧 anon JWT；静态构建 |
| `SUPABASE_SECRET_KEY` | 仅运维与 Edge Function 的高权限服务密钥 |
| `SUPABASE_ACCESS_TOKEN` | Supabase Management API 的项目管理令牌 |
| `NUXT_PUBLIC_TURNSTILE_SITE_KEY` | 公开 Turnstile site key；静态构建 |
| `NUXT_TURNSTILE_SECRET_KEY` | 运维脚本映射为 Edge secret `TURNSTILE_SECRET_KEY` |
| `ACCOUNT_ALLOWED_ORIGINS` | Edge Function 允许的 Origin，逗号分隔，默认 `https://hetwila.github.io` |

Supabase key 与管理令牌不是同一种凭据。管理令牌应限制到目标项目；部署需要读取／写入 Auth 配置、数据库、迁移历史、Edge Functions／secrets 以及读取 advisors 的权限。具体 permission 名称以锁定 CLI 的 `--help` 与官方 [PAT 文档](https://supabase.com/docs/guides/platform/personal-access-tokens) 为准。

`publicAccountConfig()` 拒绝把 `sb_secret_*` 或 `service_role` JWT 作为公开 key。私密变量不进入 Nuxt public runtimeConfig、内容导出或 Pages 产物。浏览器没有高权限 key；测试也不使用云项目凭据。

## 部署顺序

在已经通过验证的代码上运行，云环境将 `pnpm` 替换为 `bash scripts/cloud.sh`：

```bash
pnpm accounts:check
pnpm accounts:deploy
pnpm accounts:bootstrap owner@example.com
```

Codex 云环境的 Node 24 运维命令需要使用继承的 HTTPS 代理时，运行 `NODE_USE_ENV_PROXY=1 bash scripts/cloud.sh accounts:deploy`；初始化同样使用 `NODE_USE_ENV_PROXY=1 bash scripts/cloud.sh accounts:bootstrap <邮箱>`。保留平台代理与 CA 信任。需要放行 `api.supabase.com`、当前 `SUPABASE_URL` 的域名、`supabase.com`、`challenges.cloudflare.com`、`api.github.com` 和 `hetwila.github.io`；不要通过关闭代理绕过网络策略。

`accounts:deploy` 先读取项目配置，再通过官方 Management API 设置 Auth、应用未部署的迁移、写入函数 secrets，通过官方 CLI 部署两个函数、运行安全 advisors，并检查头像接口拒绝未登录请求。命令不会删除项目中的其他函数。部署可以重复运行：迁移以完整文件名登记，已部署记录中的 SHA-256 必须与源文件一致，不能修改已部署的迁移来覆盖历史。新增迁移先运行 `pnpm exec supabase migration new <名称>`。

云端迁移的版本时间戳由 Management API 生成；本脚本按记录中的完整文件名与哈希关联源文件。不要在同一项目混用本脚本和未经历史对齐的 `supabase db push`；如果以后切换到 CLI 推送，先按官方 migration repair 流程核对本地／远程版本，不能重新执行已经生效的建表 SQL。

部署会开启邮箱密码登录、关闭开放的 Auth signup、关闭邮件确认，并强制 `security_update_password_require_current_password=true`。邮箱 nonce 重新认证关闭，以免没有发信服务时无法改密。注册仅从已验证 Turnstile 的 Edge Function 进入；用户直接调用 Auth signup、伪造用户元数据或直接调用内部注册 RPC 都不能取得注册权限。如果项目已有 Auth 内置 CAPTCHA，脚本会停止并提示核对现有登录流程，避免静默覆盖它。

Turnstile 控制台需允许实际网站域名；开发时也要允许相应的 localhost 域名，并在 `ACCOUNT_ALLOWED_ORIGINS` 加入本地开发 Origin。生产环境不要使用 Cloudflare 测试 key。`NuxtTurnstile` 只负责浏览器挑战，不生成需要 Nuxt 服务器的验证端点；验证在 Supabase Edge Function 中进行，包含 success、action 与 hostname 校验。

`accounts:bootstrap` 仅在没有 admin 且目标邮箱尚未注册时创建首位管理员。它生成随机初始密码，经同样的邀请码事务创建账号，再以受控服务权限提升刚创建的 UUID。凭据仅保存到 `.secrets/first-admin.json`（文件权限 0600，目录 0700，Git 忽略），不打印密码。用户登录后修改密码并删除该文件。若初始化中断，检查文件中的 `status` 和 `userId`；不要删除凭据文件后盲目重试，也不要按未验证邮箱提升已有账号。

最后在 GitHub 仓库 **Settings → Secrets and variables → Actions** 设置三个公开变量 `SUPABASE_URL`、`SUPABASE_KEY`、`NUXT_PUBLIC_TURNSTILE_SITE_KEY`（工作流也兼容放在同名 Actions Secrets 中），重新运行 Pages 工作流。**Codex 环境变量不会自动同步到 GitHub Actions。** 后端 secret 与管理令牌无需交给 Pages 构建。没有公开配置时，静态阅读照常可用，用户中心显示“账号服务尚未配置”。

## 数据与实现约束

- `public.account_profiles`：用户 ID、邮箱、昵称、guest/admin、头像路径与时间戳。RLS 限制本人或 admin 读取；普通会话仅获得 `nickname` 的更新列权限，不能修改 email、group 或头像路径。角色不来自 `user_metadata`。
- `public.account_invitations`：6 位大写字母／数字 code、`valid_from`、`valid_until`、备注、创建者／使用者与时间戳。区间为 `[valid_from, valid_until)`，数据库使用 `timestamptz`，页面按浏览器时区输入和显示。随机 code 在数据库生成，唯一约束处理冲突。
- `account_private.registration_tickets`：只有服务角色可以发行的短期票据，绑定邮箱、昵称和邀请码，5 分钟有效。不是对外 API，也不接受客户端自选用户组。
- 注册事务：Turnstile → 服务角色 RPC 签发票据 → Auth `admin.createUser` → 延迟约束触发器读取最终 `app_metadata` → 原子核销邀请码并创建 guest 资料 → Auth 事务提交。GoTrue 在插入用户后更新 `app_metadata`，因此必须在事务提交前读取最终行，不能用普通 AFTER INSERT 触发器读取尚未写入的数据。
- 并发使用同一 code 只有一人能提交；失败回滚，不消耗邀请码。删除采用软删除并保留 code；已使用的 code 不能改名、清空使用时间或重新发行。已注册账号不受邀请码删除影响。
- `account_private` 不加入 Data API exposed schemas。必要的权限提升函数放在该私有 schema，固定 `search_path`、收紧 EXECUTE 权限；公开 RPC 使用 invoker。Auth 触发器执行于没有用户 session 的内部事务，其信任依据是服务角色签发的私有票据。
- 头像：Cropper.js 2 在浏览器中提供正方形裁剪与键盘／按钮操作，编码 8 位 PNG，最大 256×256；小图不放大。`account-avatar` 用 Auth `getUser` 验证访问令牌，检查文件大小、PNG 头、像素边界和 CRC；先丢弃辅助元信息，并用 Node zlib 的 `maxOutputLength` 限制像素数据解压大小，再由图片库解码／重编码。只限制文件头宽高不足以防止伪造 IDAT 解压膨胀。Storage 仅保存 `${userId}/${uuid}.png`。
- `account-avatars` bucket 公开读取，512 KiB、PNG；这意味着头像不是私密资料。浏览器写入被 restrictive RLS 明确禁止，即使项目已有宽泛 Storage policy 也不能绕过图片检查。上传／删除由函数服务角色完成；更新失败删除新文件，更新成功尽力清理旧文件。极端并发或清理失败可能留下未引用对象，后续可增加定期清理。
- 修改密码直接调用 `auth.updateUser({password,current_password})`，旧密码验证由 Auth 服务执行。本地集成测试会直接绕过前端验证，确认省略／填错旧密码均失败。
- 账号页面为客户端功能，带 `noindex` 与 `data-pagefind-ignore`；SSG 不读取会话、用户表或邀请码。登录状态不会改变静态百科、故事或论坛。

## AI 与普通 HTTP 客户端

机器契约见 [`/api/accounts.openapi.json`](../public/api/accounts.openapi.json)。将 server 的 `projectRef` 替换为实际项目 ID；`llms.txt` 提供入口。所有写操作遵守与网页相同的 RLS、列权限与函数验证，不需要浏览器截图。

使用公开 key 作为 `apikey`；邮箱密码登录 `POST /auth/v1/token?grant_type=password` 返回 `access_token`／`refresh_token`。之后增加 `Authorization: Bearer <access_token>`。普通 AI 客户端不得持有服务 secret 或 Management PAT；使用用户授权的会话。不要将密码或令牌放进命令行参数／日志。

| 操作 | 接口 | 权限与请求 |
| --- | --- | --- |
| 登录／刷新 | `POST /auth/v1/token?grant_type=password` 或 `refresh_token` | JSON：`email,password` 或 `refresh_token` |
| 本人 Auth 资料 | `GET /auth/v1/user` | 登录用户 |
| 修改密码 | `PUT /auth/v1/user` | JSON：`password,current_password` |
| 退出当前会话 | `POST /auth/v1/logout?scope=local` | 登录用户 |
| 获取资料／用户列表 | `GET /rest/v1/account_profiles` | guest 仅本人；admin 全部；支持 `select,order,limit,offset` |
| 修改昵称 | `PATCH /rest/v1/account_profiles?id=eq.<UUID>` | JSON：`nickname`；只允许本人 |
| 邀请码列表／创建／修改 | `GET/POST/PATCH /rest/v1/account_invitations` | admin；列表加 `deleted_at=is.null`；写入 `code,valid_from,valid_until,note`，创建时 code 可省略 |
| 删除邀请码 | `POST /rest/v1/rpc/account_delete_invitation` | admin；JSON：`target` UUID；软删除 |
| 注册 | `POST /functions/v1/account-register` | JSON：`email,password,nickname,inviteCode,turnstileToken`；必须通过真人挑战，无 CAPTCHA 旁路 |
| 头像上传／移除 | `POST /functions/v1/account-avatar` | 登录用户；`Content-Type: image/png`，PNG 二进制；空 body 恢复默认头像 |

列表使用 `order=created_at.desc,id.asc&limit=20&offset=0`，请求头 `Prefer: count=exact` 可获得 `Content-Range`。修改时使用 `Prefer: return=representation` 并检查实际返回行数；RLS 隐藏的行可能返回空列表，HTTP 200 本身不表示成功修改。

Auth 与 Data API 使用上游标准错误格式。两个自定义函数使用 `{code,message}`：400 输入／验证码／邀请码错误，401 未登录，403 来源不允许，405 方法错误，413 请求过大，503 服务不可用。注册错误不会输出完整邮箱是否存在的内部详情；函数日志不记录密码、验证码、token 或邀请码。
