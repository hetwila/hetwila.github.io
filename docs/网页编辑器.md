# 网页编辑器

入口为 [/editor](https://hetwila.github.io/editor)，也可从页脚或个人中心进入。无需登录即可编辑普通百科、故事和世界内论坛帖子；它生成仓库使用的 Markdown 文件，不直接发布，也不改变私有投稿的正文或授权。

## 撰写与下载

1. 选择百科、故事或论坛，新建本机草稿。也可以导入带 YAML 页首的 `.md`、编辑器备份 `.json`，或选择已有公开作品。导入总是生成新的本机草稿，已有草稿保留。
2. 在「撰写正文」使用可视编辑、Markdown 或阅读预览。工具栏支持标题、强调、引用和列表；「插入链接」可搜索公开文章、来源、段落和论坛楼层，也支持 HTTP(S) 外部链接。包含表格、图片、显式锚点、引用式链接等结构的段落使用 Markdown 模式，避免可视转换丢失内容。
3. 在「元数据」填写标题、中文文件名、简介、分类、发布状态、修订号等。百科和故事还包括别名、来源编号、时代／纪年、来源原文及锚点、作品关系；百科可登记正文事件并添加显式锚点。故事保持 `story-local` 和 `fiction`，论坛保持 `in-world-discussion`；已有作品的 UID 应保持稳定。
4. 论坛按楼层编辑，楼号保持原序，只能追加楼层或移除最后一层。一层可依次包含聊天和多个同人文组件；同人文填写篇名、稳定标识及正文，正文用三级标题分节。长帖只加载当前楼层的编辑框。
5. 「整篇预览」复用阅读排版；「校验与下载」检查真实 schema、来源、关系、站内链接、事件锚点和论坛结构。草稿中的未收录目标显示待核对，`published + public` 文件必须通过全部引用校验。尚未填完时可随时下载 JSON 草稿备份。
6. 点击「下载 Markdown」下载阅读版文件。故事和论坛还生成配套原稿与 SHA-256 登记片段，分别下载并按页面所列路径交付。若浏览器为同名文件增加 `(1)` 等序号，请还原所列文件名。登记片段需**合并**到既有 `manifest.json`，不要覆盖其他作品的记录。

下载文件遵循现有[百科规范](百科条目编写规范.md)和[论坛规范](论坛内容编写规范.md)。配套原稿记录本次作者编辑后的内容；编辑已有作品时，应由维护者审核修订并保留历史上传证据，不能把重新生成的原稿冒充原始附件。仅 `published + public` 会进入公开构建。完整收录仍须经过仓库检查；链接建议反映最近一次 Pages 发布的公开内容，不能提前知道其他尚未收录的文件。

## 本机自动保存

正文、楼层和元数据变化后约350毫秒写入 localStorage，刷新后恢复上次草稿。每份草稿使用独立 UUID，可切换、复制、导入、删除；清除浏览器网站数据会移除本机草稿。它不随账号登录或退出同步。存储失败会保留页面中的编辑并提示下载备份；离开页面前尝试补存。

同一草稿被另一窗口修改时，当前窗口暂停自动保存。可以「保留当前内容为副本」或「载入另一窗口版本」，不会静默覆盖另一份修改。损坏或未知版本的本机数据保留原值；导入和恢复均先校验结构。单份草稿或导入文件上限2 MiB。

localStorage 键为 `hetwila-editor:v1:<draft UUID>`，`hetwila-editor:v1:active` 记录当前 ID。备份结构由 `shared/editor.ts` 管理：`version/id/kind/updatedAt/metadata/body/posts`；元数据允许尚未填写的字段，最终导出再使用正式内容 schema 校验。草稿不会进入 Nuxt payload、Pagefind 或公开内容清单。页面要求 JavaScript，无脚本时显示使用说明。

## 管理员云端暂存

已登录的管理员可在「云端草稿」手动暂存当前编辑，列出、恢复或删除自己的快照。每次保存生成新对象，恢复时建立新的本机副本；后续编辑仍自动保存在本机，不自动覆盖云端。

使用私有 `editor-drafts` Storage bucket，仅接受 `application/json`，服务器上限4 MiB，编辑器主动限制2 MiB。路径为 `<auth.uid()>/<13位时间戳>-<标题的base64url片段>-<随机UUID>.json`；Storage key 使用 ASCII，页面解码显示标题。每页列出20份，按文件时间倒序。API 契约在 [/api/editor.openapi.json](https://hetwila.github.io/api/editor.openapi.json)。

权限在 `storage.objects` 的 RLS 中执行：必须由 `account_private.is_admin()` 确认当前受控用户组，且第一段路径为当前用户 ID。另一位管理员也不能读取此人的快照；guest、匿名用户及已撤销管理员身份者不能列出、下载、写入或删除。restrictive policy 防止项目中其他宽泛 Storage policy 绕过边界；UPDATE 被禁止，客户端使用 `upsert:false`。仅普通认证下载，不创建公开或签名链接。Storage 不负责校验 Markdown 元数据，恢复时客户端校验备份格式；发布另走文件收录流程。

迁移为 `20261105230756_editor_storage.sql`。沿用 Management API，不修改 Auth 配置：

```bash
NODE_USE_ENV_PROXY=1 bash scripts/cloud.sh content:deploy
NODE_USE_ENV_PROXY=1 bash scripts/cloud.sh editor:verify
```

## 验证范围

`tests/editor.test.ts` 对当前全部公开文章／论坛做导入导出检查，并用正式原稿读取器核对下载的原稿和哈希；还覆盖非法 Markdown／YAML、来源链接、纪年0、身份冲突及损坏备份。`pnpm test:accounts` 在真实 PostgreSQL 中执行新迁移并验证 Storage RLS，即使存在宽泛政策也不能越权。该隔离测试的 Storage 表是数据库 fixture，不是对象服务器。

浏览器测试覆盖可视编辑、元数据、链接、文件下载、本机恢复、多窗口冲突、配额失败、楼层同人文、长帖加载、云端快照 CRUD，以及手机／桌面、深浅色和无 JavaScript 页面。Storage HTTP 在浏览器测试中模拟。`editor:verify` 另外在已部署数据库中用事务临时账号验证政策，全部回滚，并通过真实 Storage HTTP 检查匿名列表；随后通过服务凭据上传、下载和删除随机路径下的临时 JSON，检查 MIME 限制及公开 URL 拒绝，并确认对象清理。不会登录真实管理员或读写其草稿；对象服务联调与普通账号的 SQL 权限校验分别执行。
