# 读者评论

评论区是独立组件，使用数据库生成的 UUID。`CommentSection` 只接收 `sectionId`，不读取文章正文、路径或标题，也不依赖文章页面存在。`/comments?id=<UUID>` 是静态生成的独立承载页，刷新链接同样可用。故事阅读页在正文及来源资料之后显示评论；百科和世界内论坛不接入读者评论。

2026-10-29：评论迁移及公开故事关联已部署到真实 Supabase。类型检查、22 项内容／Markdown 测试、45 项浏览器测试、14 项 PostgreSQL／Auth／PostgREST 集成测试和 7 项 Edge Function 测试通过；29 项真实云端检查确认投稿、所有权、两级开关、作者资料／Storage 头像及分页。前端正在进入 GitHub 检查和 Pages 发布流程，线上浏览器验收将在发布后补充。

## 数据与身份

| 表 | 用途 |
| --- | --- |
| `comment_sections` | 评论区 UUID、名称、是否接受投稿、创建／更新时间 |
| `comment_articles` | 稳定文章 UID → 评论区 UUID 的一对一关联，以及文章评论开关；当前只接受 `story:` UID |
| `article_comments` | 评论 UUID、所属评论区、作者 UUID、Markdown 原文、服务器投稿／更新时间 |
| `comment_authors` | 只包含发言者的 UUID、昵称和头像路径；数据库触发器同步资料变化，公开查询仅能看到仍有评论的作者 |
| `comment_group_permissions` | 按 `account_group` 保存投稿权限；guest 与 admin 均默认允许，普通会话不能修改 |

`account_profiles` 的邮箱及用户组读取规则保持原样。评论作者资料不通过放宽私密账号表权限来取得。昵称允许重复，身份与所有权使用 UUID。账号删除后评论保留，作者外键置空，页面显示默认头像与“已注销用户”。

故事与评论区的关联由运维同步脚本建立，使用源文件的稳定 `uid`，不是 URL 或标题。重复同步保留评论区 ID、所有评论及管理员设置，仅更新文章标题和路径。源文章移除时不会级联删除评论区，已有 ID 仍能独立使用。世界内论坛的虚构发言者与真实读者评论没有身份关联。

## 权限与开关

| 操作 | 未登录 | guest | admin |
| --- | --- | --- | --- |
| 阅读评论及公开作者资料 | 可以 | 可以 | 可以 |
| 发表评论 | 不可以 | 用户组允许且两个开关均允许 | 用户组允许且两个开关均允许 |
| 编辑评论内容 | 不可以 | 仅本人 | 仅本人 |
| 删除评论 | 不可以 | 仅本人 | 任意评论 |
| 创建独立评论区、调整评论区投稿状态 | 不可以 | 不可以 | 可以 |
| 调整关联文章评论开关 | 不可以 | 不可以 | 可以 |

独立评论区只检查自身投稿开关；有关联文章时还必须检查文章开关。关闭后保留历史评论及作者的编辑、删除能力。管理员也不能绕过关闭状态投稿，也不能改写他人的评论。即使使用独立链接、直接 REST 请求或伪造前端参数，同一评论区的规则仍然生效。

RLS、列权限和数据库函数共同执行规则。浏览器只能写评论的 `section_id,body`，只能更新 `body`；不能指定作者、转移评论归属或伪造时间。更新接口可附加旧 `updated_at` 条件，网页用此条件发现另一窗口更新／删除引起的冲突。删除为真实删除，网页先显示确认框。

管理员在用户中心的“评论区”标签内查看 ID、关联故事及独立链接，创建无文章关联的评论区，设置两个开关；也可以直接在评论区调整开关和删除评论。关联关系本身仅由运维同步维护，普通管理员网页操作不能将故事评论移到别的评论区。

## Markdown 与阅读体验

- 支持段落、强调、删除线、引用、有序／无序列表、任务列表、链接、图片、行内／围栏代码及表格；每条最多 10,000 个字符，列表每页 20 条，按投稿时间与 UUID 稳定排序。
- 使用现有 `remark-parse`／`remark-gfm` 解析为 AST，再由固定 Vue 标签白名单渲染；不使用 `v-html`，不解释 HTML、MDC、Vue 组件、事件、内联样式或用户指定的 class／id。原始 HTML 作为文本显示。
- Markdown 标题统一呈现为评论正文大小的加粗段落，不新增页面标题或目录锚点。图片限制高度，代码与表格在评论内部滚动，长文本换行；样式只作用于 `.comment-markdown`。
- 链接／图片仅接受 HTTP(S) 地址，拒绝脚本协议、数据协议、控制字符和带账号密码的 URL。外链带 `ugc nofollow noopener noreferrer`，图片使用延迟加载及 `no-referrer`。
- 投稿和编辑均可预览，失败时保留草稿供重试；发布和更新时间都使用数据库时间，按读者本地时区显示。评论从 Supabase 在浏览器中加载，不进入静态正文、Pagefind、故事原稿哈希或世界观事实导出。
- Supabase 不可用或禁用 JavaScript 时，已发布故事正文仍可完整阅读。独立页与评论区带 `data-pagefind-ignore`，独立页另带 `noindex`。

## 组件接入

```vue
<script setup lang="ts">
import CommentSection from '~/components/comments/CommentSection.vue'
</script>
<template>
  <CommentSection section-id="数据库中的评论区 UUID" />
</template>
```

`ArticleComments` 是故事页的薄适配层：按 `articleUid` 查询关联后，把得到的 UUID 交给同一个组件。无需给 `CommentSection` 传入文章对象。

## 部署与新增故事

先运行类型检查、`pnpm test:accounts` 和 `pnpm test`。云环境均使用 `bash scripts/cloud.sh` 包装。然后使用现有 Management API 迁移历史部署：

```bash
NODE_USE_ENV_PROXY=1 bash scripts/cloud.sh comments:deploy
```

此命令校验已部署迁移的 SHA-256，应用新增迁移，同步所有 `published + public` 故事的 UID 关联并读取安全 advisors。它不修改 Auth 设置、函数 secrets 或管理员账号，也不重新部署注册／头像函数。`accounts:deploy` 的完整安装流程同样会同步故事关联。不要混用未经历史对齐的 `supabase db push`，不要为评论功能重跑 bootstrap。

新增故事或改名后，在发布前再次运行 `comments:deploy`，建立新关联或更新路径；既有两个开关不会被重置。Pages 仍只需要原来的三个公开变量，不增加服务端或私密构建变量。普通账号不能用随意的 UUID 自动创建评论区。

## HTTP 与验证

机器契约：[comments.openapi.json](../public/api/comments.openapi.json)。使用公开 `apikey` 阅读，写操作另附用户会话 Bearer token。主要接口为 `/rest/v1/comment_sections`、`comment_articles`、`article_comments`、`comment_authors` 和 `/rest/v1/rpc/comment_can_post`。前端通过官方 `supabase-js` 调用相同接口。

读取评论可使用 `select=id,section_id,author_id,body,created_at,updated_at,author:comment_authors(nickname,avatar_path)`，并指定 `section_id=eq.<UUID>&order=created_at.asc,id.asc&limit=20&offset=0`。`Prefer: count=exact` 返回分页总数。写操作用 `Prefer: return=representation` 并检查实际返回行数；RLS 隐藏的目标可能返回空数组，HTTP 200 不表示已经修改成功。

测试覆盖真实 PostgreSQL／Auth／PostgREST 的权限、两级开关、用户组能力、不可写字段、作者资料投影、删除账号、分页和同步幂等；Markdown 测试覆盖 HTML／脚本协议隔离。浏览器测试覆盖故事与独立页、投稿预览、编辑删除、管理员设置、错误恢复、深浅主题、桌面／手机、样式边界及可访问性。浏览器模拟不等同于真实云端验收。
